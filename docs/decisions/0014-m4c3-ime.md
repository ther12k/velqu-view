# ADR 0014: M4c3 — IME composition; preedit is presentation, commit is the edit

Status: accepted (M4c3)

## Context

M4c1/M4c2 built editable controls and clipboard on one architecture: the
renderer owns editor semantics as runtime state, the host owns OS
services. IME follows the same split, against a gate pre-registered in
`docs/evidence/m4c3-gate.md` before implementation. The rules below are
the reviewer-frozen design; the freeze evidence in
`docs/evidence/m4c3-verification.md` answers every gate scenario.

## Decision

### 1. Preedit is presentation state; only Commit mutates the value

`ControlState` gains `composition: Option<CompositionState>` — the
preedit `text`, its `cursor` (byte offsets), and the `range` of the
value a commit will replace (the selection captured at composition
start). The editor paints an *effective text* (value with the
composition spliced over its range) with a composition underline and
the caret at the composition cursor; the real value, `LayoutFacts`,
and `ValueChanged` are untouched, and zero Taffy passes run — the same
presentation contract as M4b/M4c1 editing. An update replaces the
composition rather than appending; empty preedit text clears the
presentation while the session stays live for winit's following
commit.

### 2. Commit is one atomic edit through the shared filter

`ime_commit` replaces the composition's range (or the selection,
without one) with the committed text filtered by the same
`ControlKind::filter_text` keyboard insertion and paste use — no
fourth normalization path — and emits `ValueChanged` then
`SelectionChanged` exactly once via M4c1's `finish_control_change`.
If the filter empties the text (e.g. a lone newline into an input),
the replaced selection still collapses and nothing is inserted.

### 3. Composition is session-scoped

IME events are window-level and carry no element identity. Composition
start captures `ImeSession { owner: NodeId, document_generation }`;
every later preedit/commit is checked against it. The session — and
the preedit with it — cancels on focus transfer (a later Commit for
the old owner is a stale no-op that cannot touch the newly focused
control), on window blur (the shell maps `Focused(false)` and
`Ime::Disabled` to `ime_cancel`), and on document reload. Readonly or
disabled controls never start a session; a control that is no longer
editable at commit time drops the composition without editing.

### 4. Keyboard input yields to the composition

While a composition is active, `insert_text` and every `key_command`
are refused: winit documents that `KeyboardInput` should be suppressed
during preedit, and an open winit/Windows issue means it sometimes
isn't — so `Ime::Commit` is the only insertion source. The gate's
regression (`Preedit("a")` + stray text `"a"` + `Commit("あ")` ⇒
`"あ"`) is pinned.

### 5. Platform indexes are never trusted

Preedit cursor byte ranges are clamped to the preedit text's length on
valid UTF-8 boundaries and ordered before use (`CompositionState::new`).
Out-of-range and non-boundary indexes cannot panic (winit 0.30.13
itself fixed an out-of-bounds macOS Pinyin crash on its side; Velqu
guards its own).

### 6. Enablement belongs to the shell

The renderer exposes `wants_ime()` (true exactly when an editable
control holds focus) and `ime_cursor_rect(viewport)` — the caret or
composition-cursor rectangle in **viewport device pixels**, mapped
through the document and ancestor scroll transforms (the same math as
hit testing, inverted; `None` on cache miss per the no-implicit-layout
rule). The shell translates winit's `Ime` events onto
`ime_preedit`/`ime_commit`/`ime_cancel`, drives
`Window::set_ime_allowed` from `wants_ime`, and pushes
`set_ime_cursor_area` in physical pixels with change-gating. The
anchor is re-read after keyboard/pointer input, wheel scrolling
(ancestor scrolls move it), redraws (scroll-to-caret), window focus,
and IME events themselves. No winit type enters `velqu-view`.

## Consequences

* The renderer remains host-independent: composition state is editor
  runtime state next to value/selection; the shell merely translates
  platform events and positions the native candidate window.
* The M4c editing stack closes consistently: value mutation happens
  only through the shared filter — keyboard, paste, and commit — and
  preedit/selection/caret all repaint without Taffy.
* Fixed profile styling for the composition underline (2px rule) joins
  the M4c1 chrome colors; author styling of composition marks is out
  of profile.
* Synthetic tests pin the renderer contract and the Windows-shape
  stray-input regression; real IME behavior (candidate windows,
  preedit round-trips) needs windowed platform smoke — Wayland and X11
  now, Windows and macOS eventually — recorded in the verification
  evidence, since unit tests cannot establish that whole contract.
